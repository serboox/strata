Куда уходит времяWhere the time goes

Сгенерировано 10 466 токенов (около 317 с при 33 ток/с, то есть 9%); 295 тыс. токенов промпта прочитаны заново, а 120 ходов из 128 шли с контекстом больше 16K. In the fresh short tasks the context stayed under 6.6K and decode took 44%.

B2. Спекулятивное сэмплированиеSpeculative sampling

Реализовано в движке (флаг STRATA_Q36_SPEC_SAMPLING=1, по умолчанию выключен): черновик MTP остаётся жадным, окно проверки отдаёт логиты всех строк, черновик принимается с вероятностью, которую ему даёт сэмплирование (temperature, top_k, top_p, min_p, штрафы по истории с принятыми токенами), при отказе токен берётся из остатка распределения. Это точный вариант для черновика из одного токена. Greedy-запросы идут прежним путём.Implemented in the engine (flag STRATA_Q36_SPEC_SAMPLING=1, off by default): the MTP draft stays greedy, the verify window returns the logits of all rows, a draft is accepted with the probability the sampling gives it (temperature, top_k, top_p, min_p, penalties over the history including accepted tokens), and on rejection the token is drawn from the remaining distribution. This is the exact variant for a one-token draft. Greedy requests keep the old path.

B4. Ядра CPU (VNNI)CPU kernels (VNNI)

Микротест kq512_parity --bench: побитовое совпадение с ggml (200 случаев, 0 расхождений) и пропускная способность ядер AVX-512. На одном токене ядро почти упирается в память; на 2-3 токенах падает, то есть становится вычислительным.Micro-benchmark kq512_parity --bench: bit-exactness against ggml (200 cases, 0 mismatches) and AVX-512 kernel throughput. With one token the kernel nearly hits the memory roof; with 2-3 tokens it drops, i.e. becomes compute-bound.

Распаковка веса один раз на несколько токенов в ядре уже есть, так что посылка B4 устарела. VNNI не уменьшает число операций: у Q4_K и Q5_K у каждой группы из 32 значений своя шкала, поэтому после dpbusd нужно умножение на шкалу, и выходит те же 3 операции на 64 веса (maddubs, madd, add). Остаётся хвост общих экспертов (оценка при допущении 62/30/8% чтений на 1/2/3 токена, среднее 1,42 токена на набор весов, около 40% чтений); если бы там удалось выйти на 48 ГБ/с, ядра ускорились бы не более чем на 15%, а шаг не более чем на 6%. Прототип не строился.The kernel already unpacks a weight once for several tokens, so the premise of B4 is outdated. VNNI does not cut the operation count: in Q4_K and Q5_K every group of 32 values has its own scale, so a multiply by the scale follows dpbusd, giving the same 3 operations per 64 weights (maddubs, madd, add). What remains is the tail of shared experts (an estimate assuming 62/30/8% of reads at 1/2/3 tokens, mean 1.42 tokens per weight set, about 40% of reads); reaching 48 GB/s there would speed the kernels up by at most 15% and a step by at most 6%. No prototype was built.

B5. n-gram на длинных совпаденияхn-gram on long matches

Симуляция на трёх наборах: самое длинное совпадение суффикса в контексте даёт черновик до kmax токенов; иначе MTP 2. Стоимость из измерений B1: шаг 44,3 мс плюс 20,8 мс за каждую лишнюю строку, MTP 2 даёт 31,0 мс на токен. Лучшие параметры подобраны задним числом по каждому набору, то есть оценка оптимистична.Simulation on three datasets: the longest suffix match in the context gives a draft of up to kmax tokens; otherwise MTP 2. Costs come from the B1 measurements: a step is 44.3 ms plus 20.8 ms per extra row, and MTP 2 gives 31.0 ms per token. The best parameters were picked after the fact for each dataset, so the estimate is optimistic.
